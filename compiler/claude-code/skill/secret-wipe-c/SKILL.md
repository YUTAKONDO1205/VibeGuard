# 秘密データの消去処理（C）

秘密データを置いた領域は、使い終わったら関数を抜ける前にゼロで上書きする（以下、消去処理）。
ただし、その後に読まれない領域への書き込みは、コンパイラが最適化（dead store elimination）で削除してよい。
`memset(buf, 0, n);` をそのまま書くと、-O1 以上で削除されることがある（CWE-14、CERT C MSC06-C）。

## 書き方

1. 消去処理は、秘密を置いた全ての領域（スタックの配列、ヒープの領域、構造体の秘密のメンバ）に対して、
   正常の戻りとエラーの戻りの全ての経路で行う。ヒープは free の前に行う。
2. `memset` をそのまま使わない。次のどれかを使う。
   - `explicit_bzero(buf, n);`（glibc 2.25 以降、BSD。`#include <string.h>`。`-std=c11` などでは `_DEFAULT_SOURCE` が要る）
   - `memset_s(buf, n, 0, n);`（C11 Annex K を提供する環境だけ。glibc には無い）
   - どちらも無い環境では、`volatile` なポインタで 1 バイトずつ書くループ、または
     `memset` の直後に `__asm__ __volatile__("" : : "r"(buf) : "memory");` を置く
3. 消去処理の行の末尾に `/* wipe */` と書く（下の確認スクリプトが、この印の行を消去処理として扱う）。
4. 環境で書き方を切り替えるとき（`#if`）は、どの分岐も 2 の書き方にする。関数の有無を `#ifndef explicit_bzero` で調べない
   （explicit_bzero はマクロではなく関数なので、この条件は常に真になる）。

## 確認（コマンドを実行できるとき）

書いた後に、-O2 でコンパイルしても消去処理が残っているかを確かめる。

```
python3 scripts/check_wipe.py <ファイル.c> <関数名> [--cc gcc,clang] [--cflags "-D_FORTIFY_SOURCE=2"]
```

- 消去処理の行（`/* wipe */` の行。印が無ければ memset・explicit_bzero などの呼び出し）を除いた版を作り、
  元の版と同じ設定でコンパイルして、対象の関数の命令列を比べる。同じなら、消去処理は最適化で削除されている。
- 終了コード 0：全てのコンパイラで残った。1：どれかで削除された。2：消去処理が見つからない、またはコンパイルできない。
- 1 または 2 のときは、書き方の 2 に従って書き直し、もう一度確かめる。
- このスクリプトが見るのは、指定した関数の命令列だけである。補助関数の中の消去は、補助関数の名前でも確かめる。
  「残った」は、命令列の上で消去処理が削除されなかったという意味であり、秘密データがメモリに残らないことの保証ではない。
